Exhibit 00 · the idea

When a print stops, three questions matter.

The U1's exported system logs are encrypted and only Snapmaker support can open them (official wiki). U1 Doctor gives the owner evidence they can read, keep and share. It never controls the printer.

01

What does this error code mean?

An offline decoder with a link to the official page. An unknown code gives INCONCLUSIVE, never a guess.

02

What happened, and when?

A timeline built only from observed facts, with explicit gaps and the source of every row.

03

What can I show someone else?

A portable evidence bundle, U1-DEB, that anyone can open and replay locally.

Exhibit 01 · the principle

Every fact keeps its source.

Observations go through a pure function with a pinned rule set. The same input and the same rules always give the same findings and the same hash.

Exhibit 03 · determinism

      
Same input. Same result.

      
The engine is a pure function. Replay the same observations with the same rule set and you get the same findings and the same hash, byte for byte.

      
  • Declarative JSON rules, pinned by a hash
  • Unknown = INCONCLUSIVE, never a guess
  • No score, no percentage

    

    

    
    

  







  

    
Exhibit 04 · the timeline

    
Gaps stay gaps.

    
The timeline describes the observed window, row by row, with its source and time quality. A gap is drawn as a gap. It never means "nothing happened".

    

    
Real captures: a 27-minute normal print (9,333 frames) shipped with the app, and a 55-minute multi-colour print (18,339 frames, derived evidence only), both from the owner's own U1. No real fault has been captured yet: every incident you can open in the app is SYNTHETIC.

  







  

    

    
    

    

      
Exhibit 05 · the findings

      
No score. Evidence.

      
Every finding shows its evidence for, evidence against, what is missing, its limits and its official references. It points back to the observations that produced it.

      
  • Classification, quality and hypothesis always labelled
  • A Dry Run rule stays "SUSPECTED, WEAK": a community simulator, not proof

Get it · share it

    
Take it. Help it learn.

    
A Windows executable, no Python to install. And a project that lacks one thing only the community can give: real incidents.

  

  

    

      
Download

      
Windows, in two minutes

      
    
        
  • Download the zip of the latest release, check its SHA-256 (given in the notes), extract it with "Extract all", double-click u1-doctor.exe.
    • 
        
  • A window opens with the app (no console, no browser): it starts in DEMO mode, offline, with clearly labelled synthetic data. If the Microsoft WebView2 component is missing, it offers to install it once.
    • 
        
  • For your U1: Connect screen, type its private address, tick the approval box, start the read-only capture.
    • 
        
  • The executable is not code-signed, so Windows SmartScreen may warn. Linux, macOS and Docker: see the install guide.
    •

Share an incident

      
One real incident is worth ten scenarios

      
So far only normal prints have been captured on a real U1: every incident in the app is synthetic. A real error code, with the firmware and the moment, lets the rules be checked.

      
    
        
  • Describe what happened: exact error code, firmware, moment, what you saw.

Exhibit 08 · the bundle

    
Evidence that travels.

    
The bundle is a zip with a fixed file allowlist. You can export one from your own saved captures on the Report screen. On import everything is strictly validated, observations are labelled IMPORTED and findings are recomputed with your rules. A SHA-256 proves integrity, never the author.

    

    
    

  







  

    
Exhibit 09 · safety

    
It can look. It cannot touch.

    
A frozen allowlist is checked before any network I/O. Everything outside it stays refused, and tests keep it that way. The app listens on 127.0.0.1 only.

    

    
    

    
Several supervised sessions have been run on the owner's U1, with GET requests, object reads and one WebSocket subscribe only. No write was sent (0 non-read operations in every audit log).

  







  

    
Exhibit 10 · limits

    
What it does not claim.

    
Status: work in progress, prepared for the Snapmaker U1 Innovation Fund. This build reads a printer only with the owner's explicit consent (address typed, box ticked, read-only) and never sends a command that changes it. Every incident you can open in the app is badged SYNTHETIC, and the real captures show normal prints.

    
    
      
  • A lost connection never means the printer stopped.
    • 
      
  • The timeline describes the observed window only. No gap record does not prove the data is complete.
    • 
      
  • Timestamps are the PC's receipt time unless proven otherwise.
    • 
      
  • A SHA-256 on a bundle proves integrity only, never who made it.
    • 
      
  • The decoder reports what the code says, not a diagnosis. The official wiki warns that the displayed code may not be the real fault.
    • 
      
  • Export redaction is best effort, not a guarantee of anonymity.
