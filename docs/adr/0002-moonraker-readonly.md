# ADR-0002 — Read-only Moonraker transport
Status: Accepted (G0), implemented as policy + mocked client · Date: 2026-11-05

**Decision.** `ReadOnlyMoonrakerTransport` exposes exactly: `get_server_info`, `get_printer_info`, `list_objects`, `query_objects`. Allowlist = `GET /server/info`, `GET /printer/info`, `GET /printer/objects/list`, `POST /printer/objects/query` (validated body). WS: only JSON-RPC `printer.objects.subscribe`, validated frame. Denied until a formal audit adds them: `GET /printer/objects/query`, WS `server.info`/`printer.info`, `server.connection.identify`. Target = literal RFC1918 IPv4:7125. `trust_env=False`, no redirects, size caps, owner `Consent` for real network. Verb is never trusted alone (the one allowed POST is body-validated).
**Why.** Cahier §6; Moonraker mutating calls exist on the same server (see source-audit §3).
**Consequences.** Some useful reads (identify, GET query) need an audit; the 192.0.0.0/8 trusted range upstream is wider than RFC1918 but we stay stricter. Checks live in `backend/app/transport/policy.py`; any new route = ADR amendment + negative test.
**Amendment 2026-11-05 (WebSocket).** `ReadOnlyMoonrakerWebSocket` (`backend/app/transport/ws.py`): only `subscribe()` can send, frame validated by `check_ws_message` before any I/O; no generic send; inbound parsed, capped (256 kB), never answered; `proxy=None`, no compression; same RFC1918:7125 + owner Consent rule. New dependency `websockets>=15,<16` (BSD-3, pure Python). Tests: `backend/tests/test_ws.py`. Not yet run against the real U1 (H-02 needs owner go).
**Not covered.** Real-hardware WebSocket behaviour (H-02).
**Amendment 2026-11-08 (audit, BACKLOG #52 L3/L4).** `POST /printer/objects/query` and `query_objects` are removed: the app never used them and they never ran on the machine. The allowlist is now GET only (`/server/info`, `/printer/info`, `/printer/objects/list`) plus WS `printer.objects.subscribe`; any POST is refused. The real WebSocket client is opened with `ping_interval=None`: no keepalive pings, so the only data frame sent is the subscribe message (the library still answers pings and closes cleanly).
**Amendment 2026-11-08 (BACKLOG #57 live rules, #59 connectivity self-check; owner decision: defensive code, UNTESTED).** Minimal widening, each item justified:
1. *One new GET:* `GET /server/files/directory?path=logs` (tag `server.files.directory`, method `get_logs_disk_usage`). Needed by rule S22 (log partition usage, forum topic 41445: logs and configuration share a 100 MB partition). Moonraker has no disk-usage-only route; this is the smallest documented one (`disk_usage` of the partition holding the root). Policy: new `ALLOWED_HTTP_QUERY` = exact path + exact key `path` + exact value `logs`; any other key, value, path or method is refused before I/O, and every other path still takes no query. Only `disk_usage.total/used/free` is kept; the file list is dropped unread. One read, not two: the forum describes one partition for config and logs (limit stated in the rule). A failure (404 on a printer without a `logs` root) only makes S22 say "not observable".
2. *No new request, wider subscribe:* the single subscribe frame also names `temperature_sensor cavity` (`temperature`) and `bed_mesh` (`probed_matrix`), both listed by the real U1 (H-01 object list) but never subscribed to on one. Policy: new `ALLOWED_SUBSCRIBE_OBJECTS`, exact object names; anything else is refused before I/O. Offsets, nozzle diameters, toolhead states and counters, `toolhead.estimated_print_time` and the frame `eventtime` were already in the H-02 subscription (all fields of `extruder*` and `toolhead`).
3. *Rejected:* `/machine/proc_stats` and `/machine/system_info` (host uptime is the frame `eventtime`; system_info carries network identifiers), `/printer/objects/query` (subscribe already gives the same objects), reading `configfile` (whole configuration, can exceed the 256 kB frame cap), a second directory read for `config`, any reconnect of the stream.
Budget: **4 GET + 1 WebSocket message; if the stream drops, up to 6 more status GET: 10 GET at most** (`app.live.MAX_GET`, `MAX_WS_SENT`; a tripwire stops the capture above it). The consent text (FR/EN) states these numbers and `tests/test_live_rules.py` fails if text and code disagree. Connectivity facts (latency per GET, drops, reconnects = 0 by design, address changed or not) come from these same requests. Tests: allowed and denied variants in `backend/tests/test_live_rules.py`. Not run against a real U1.
